# 变更规范（delta）：garfish-parent-shell

## 修改后的要求

### 要求：Shell 提供基础布局
父容器（门户 Shell）应渲染门户页面的基础布局，包含用于路由内容的主内容区域。

#### 场景：初次渲染
- **当** 父容器启动
- **则** 渲染用于门户路由内容的主内容区域

## 新增要求

### 要求：Shell 支持通过 query 参数的应用跳转入口
父容器应在首页路径支持基于 query 的应用跳转入口：`/?appName=<name>&returnUrl=<encoded-url>`。

#### 场景：跳转入口根据 appName 重定向到目标应用
- **当** 当前 URL 包含有效的 `appName` 且匹配到已配置的应用
- **则** 父容器以浏览器级重定向跳转到该应用的配置 url

#### 场景：重定向时透传 appName
- **当** 父容器重定向到配置的应用 url
- **则** 应在目标应用 url 上追加（或覆盖）`appName` query 参数

#### 场景：重定向时透传 returnUrl
- **当** 父容器重定向到配置的应用 url
- **则** 应在目标应用 url 上追加（或覆盖）`returnUrl` query 参数，值为当前页面 query 中 `returnUrl` 解码后的地址

#### 场景：缺省 returnUrl 使用默认值
- **当** 当前 URL 包含有效 `appName` 但缺少 `returnUrl`
- **则** 父容器仍跳转到配置的应用 url，并将 `returnUrl` 设置为门户首页绝对地址

#### 场景：未知 appName 不跳转并展示错误状态
- **当** 当前 URL 包含 `appName` 但不匹配任何已配置应用
- **则** 父容器不应重定向，并展示未找到/错误提示

## 移除要求

### 要求：Garfish 初始化与注册
**原因**：门户不再接入 Garfish，移除子应用注册/初始化链路。
**迁移**：删除 Garfish 初始化与注册逻辑，改为基于配置的浏览器级重定向。

### 要求：Garfish 加载与渲染子应用内容
**原因**：门户不再在页面内加载/渲染子应用内容。
**迁移**：删除子应用容器渲染与加载逻辑，应用入口仅负责跳转到目标应用 url。

### 要求：子应用加载失败错误页
**原因**：不再存在“子应用加载失败”的运行时路径。
**迁移**：目标应用自行处理加载错误；门户仅处理“未知 appName/无配置”等本地错误。
