# 变更规范（delta）：subapp-navigation

## 新增要求

### 要求：应用跳转入口使用 query 参数
门户应使用 query 驱动的入口来启动应用：`/?appName=<name>&returnUrl=<encoded-url>`。

#### 场景：使用 query 参数启动
- **当** 用户在门户发起应用启动
- **则** 门户导航到 `/?appName=<name>&returnUrl=<encoded-url>`

### 要求：returnUrl 为当前页面地址
门户应将 `returnUrl` 设置为发起启动时的当前页面地址，并进行 URL 编码。

#### 场景：生成 returnUrl
- **当** 用户点击门户中的应用入口
- **则** 门户将 `returnUrl` 设置为 URL 编码后的当前页面地址

### 要求：目标应用支持返回门户
门户应将 `returnUrl` 作为稳定参数透传给目标应用，以便目标应用可“返回”到门户。

#### 场景：透传 returnUrl
- **当** 门户重定向到目标应用
- **则** 目标应用收到 `returnUrl` query 参数

#### 场景：透传 appName（用于目标应用识别）
- **当** 门户重定向到目标应用
- **则** 目标应用收到 `appName` query 参数

## 移除要求

### 要求：仅在子应用视图显示顶部导航
**原因**：门户不再存在子应用视图与子应用内导航条。
**迁移**：移除子应用路由下的顶部导航渲染逻辑。

### 要求：导航条居中显示子应用名
**原因**：不再存在子应用内导航条与子应用标题展示。
**迁移**：移除以子应用名为中心的导航布局。

### 要求：紧凑导航高度
**原因**：不再渲染子应用内顶部导航。
**迁移**：删除相关样式与组件逻辑。

### 要求：子应用视图内 Home 按钮
**原因**：不再存在从子应用视图返回门户的导航按钮。
**迁移**：门户返回能力通过 `returnUrl` 由目标应用实现；门户侧不再提供子应用内 Home 按钮。

### 要求：Home 按钮使用 icon
**原因**：同上，不再存在该按钮。
**迁移**：删除相关 icon button 逻辑。
