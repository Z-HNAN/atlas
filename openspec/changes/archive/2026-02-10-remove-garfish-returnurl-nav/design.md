## Context

现状：门户工程当前以“父容器 + 子应用”方式工作，依赖 Garfish 完成子应用注册与渲染；Home 页展示子应用卡片，点击进入子应用视图（并显示顶部导航）。

问题：
- Garfish 引入了额外的运行时依赖、初始化顺序与错误处理分支，且与“仅做入口跳转”的门户定位不匹配。
- 目前跳转入口缺少统一的可分享/可回跳参数约定，难以在目标应用侧统一实现“返回门户”。
- Home 页卡片密度偏大，窄屏/移动端观感与信息密度不理想。

约束：
- 本次变更以“移除 Garfish 接入、移除子应用渲染逻辑”为前提。
- 仍保留应用配置的本地管理能力（新增/删除/持久化）。
- 需要引入统一的入口参数：`/?appName=<应用名>&returnUrl=<URL-encoded>`，其中 `returnUrl` 为发起跳转时的当前页面地址。

## Goals / Non-Goals

**Goals:**
- 移除 Garfish 以及子应用渲染相关代码路径，门户仅负责“配置管理 + 入口跳转”。
- 统一跳转入口为 query 参数驱动：`appName` 用于选择目标应用，`returnUrl` 用于目标应用回跳。
- Home 页“应用块”变更为更紧凑的响应式卡片布局。

**Non-Goals:**
- 不定义/不实现目标应用内部的返回按钮与跳转逻辑（仅提供 `returnUrl` 作为约定参数）。
- 不引入新的后端服务或远程配置中心；应用配置仍为本地持久化。
- 不要求支持 Garfish 微前端能力的兼容模式。

## Decisions

1) 以“门户重定向”替代“门户内渲染子应用”
- 决策：点击应用卡片后，门户生成并跳转到 `/?appName=...&returnUrl=...`；门户在检测到 `appName` 时，根据本地配置查找目标应用 URL，并执行浏览器级重定向到目标应用。
- 理由：完全移除子应用渲染链路与容器约束，符合“页面不需要接入 Garfish/去除子应用逻辑”的目标；同时保留可分享的统一入口形态。
- 备选方案：
  - iframe 内嵌目标应用：可控但仍属于“子应用渲染逻辑”，且有跨域、登录态、尺寸适配等复杂性。
  - 保留 Garfish 但仅用于部分应用：与“去除所有内容”冲突，且维护成本仍高。

2) `returnUrl` 生成规则固定为“发起跳转时的当前页面地址”
- 决策：在 Home 页点击卡片时，使用 `window.location.href`（或等价路由生成的绝对 URL）作为来源，并使用 `encodeURIComponent` 编码写入 query。
- 理由：语义清晰，支持从任意入口页发起跳转；目标应用无需理解门户路由，只需使用 `returnUrl` 即可回跳。
- 备选方案：仅传相对路径：对跨域门户/多环境不友好。

3) `appName` 查找失败的处理
- 决策：当 `appName` 不存在于本地配置中时，门户展示明确错误（例如 NotFound/错误提示）并提供返回 Home 的入口。
- 理由：避免静默失败或跳转到错误地址。

4) 卡片布局与响应式策略
- 决策：使用 CSS Grid（`grid-template-columns: repeat(auto-fit, minmax(...)))`）实现响应式列数；卡片 padding、字体、图标尺寸整体下调；在窄屏下保证可点击区域不小于可用阈值。
- 理由：实现成本低、表现稳定、易维护。

## Risks / Trade-offs

- [目标应用不支持 `returnUrl`] → 在规范中将其定义为“门户提供的回跳参数约定”，并在 UI 文案中明确“由目标应用决定是否使用”。
- [重定向导致门户页面状态丢失] → 依赖本地持久化存储配置；门户本身不承担复杂的会话态。
- [潜在的开放重定向误用] → 门户的跳转目标只能来自本地配置的应用 URL，不允许直接用 `returnUrl` 决定跳转目的。

## Migration Plan

- 移除 Garfish 依赖与初始化代码；删除子应用渲染页面/路由。
- 调整 Home 页卡片点击行为，生成 `/?appName=...&returnUrl=...` 入口并触发跳转。
- 在应用启动/路由层增加 `appName` 检测：存在则查配置并重定向到目标应用 URL（将 `returnUrl` 透传给目标应用）。
- 更新相关规范（garfish-parent-shell、subapp-navigation、subapp-management）。
- 回滚策略：保留变更前版本构建产物（或 git 回滚）；由于无数据迁移，回滚风险低。

## Open Questions

- 目标应用期望的回跳参数名是否统一为 `returnUrl`？若存在历史兼容参数（如 `redirect`/`backUrl`），是否需要同时传递？
- 跳转方式是否需要默认“新标签页打开”而非当前页重定向？（当前设计为当前页重定向，符合“跳转”语义。）
