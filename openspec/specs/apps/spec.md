# apps

## 术语与定义
- **应用**：由 `name` 与 `url` 描述的外部应用入口。
- **跳转入口**：门户用于触发跳转的入口 URL：`/?appName=<name>&returnUrl=<encoded-url>`。
- **returnUrl**：目标应用用于“返回门户”的地址。

## 规范目标
- 统一应用配置（新增/删除/持久化）与启动协议（跳转入口 + 重定向 + 参数透传）。
- 门户只做浏览器级跳转，不内嵌渲染外部应用。

## 功能与行为

### 要求：新增应用
- **当** 用户在 `/settings` 填写 `name` 与 `url` 并提交
- **则** 应用写入本地配置并返回首页

- **当** `name` 或 `url` 为空
- **则** 阻止提交并提示错误

- **当** `url` 不是合法 URL
- **则** 阻止提交并提示错误

### 要求：删除应用
- **当** 用户在首页点击删除按钮
- **则** 弹出确认；确认后从本地配置移除并从列表消失

### 要求：本地持久化
- **当** 门户刷新或重新打开
- **则** 从本地存储恢复应用配置

### 要求：首页卡片（紧凑 + 响应式）
- **当** 首页渲染应用列表
- **则** 使用响应式网格展示紧凑卡片，并保持可点击性

## 启动协议与重定向

### 要求：跳转入口协议
- 参数：
  - `appName`：应用名称（精确匹配已配置应用）。
  - `returnUrl`：URL 编码后的“当前页面地址”。

- **当** 用户点击某个应用卡片
- **则** 门户导航到 `/?appName=<appName>&returnUrl=<encodeURIComponent(currentUrl)>`

### 要求：重定向规则
- **当** 门户检测到 `appName`
- **则** 按本地配置查找目标应用并执行浏览器级跳转

- **当** `appName` 为空或无法匹配任何已配置应用
- **则** 门户不跳转，展示错误状态并允许返回首页

### 要求：透传参数到目标应用
- **当** 门户跳转到目标应用
- **则** 在目标 URL 上追加（或覆盖）以下 query：
  - `appName=<appName>`
  - `returnUrl=<decodedReturnUrl>`

### 要求：returnUrl 默认与校验
- **当** `returnUrl` 缺失、为空或无法解析为合法 URL
- **则** 回落为“门户首页绝对地址”作为 `returnUrl`

## 安全约束
- 目标跳转地址只能来自“本地已配置应用的 url”，不得由 `returnUrl` 等外部参数决定。
