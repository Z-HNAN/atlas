# portal-shell

## 术语与定义
- **门户**：当前站点（gipsy），负责展示应用列表并跳转到外部应用。
- **应用**：由 `name` 与 `url` 描述的外部应用入口。

## 规范目标
- 门户只负责“配置 + 导航”，不在页面内加载/渲染外部应用内容。
- 门户提供清晰的页面路由与基础布局。

## 功能与行为

### 要求：提供基础路由
- **当** 用户访问 `/`
- **则** 渲染门户首页（应用卡片网格）或进入“跳转处理”（详见 `apps` 规范）

- **当** 用户访问 `/settings`
- **则** 渲染应用新增页面

- **当** 用户访问其它路径
- **则** 展示未找到页面，并提供返回首页入口

### 要求：不内嵌加载外部应用
- **当** 用户点击某个应用
- **则** 门户以浏览器级跳转打开外部应用，而不是在门户页面内渲染

### 要求：品牌标识（gipsy）
- **当** 用户打开门户
- **则** 浏览器标签页标题为 “gipsy”

- **当** 用户进入首页
- **则** 页面内标题为 “gipsy”

### 要求：PWA（manifest + service worker）
- **当** 浏览器请求 `/manifest.webmanifest`
- **则** 返回合法 manifest，且 `name/short_name` 为 “gipsy”

- **当** 门户在支持 service worker 的浏览器中加载
- **则** 尝试注册 service worker，并预缓存构建产物以支持离线启动

- **当** 检测到新版本 service worker 已就绪
- **则** 提示用户刷新以更新

- 约束：默认只做构建产物预缓存，不做运行时缓存（除非明确配置）
